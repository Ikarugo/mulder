# Mulder v1.5.1

Changes since [v1.5.0](https://github.com/calebevans/mulder/releases/tag/v1.5.0).

## Investigation reliability and local models

- Reject malformed planner task lists before execution, validate repaired plans,
  and tolerate malformed task entries in the dashboard. Invalid plans now fail
  cleanly if the existing repair attempt cannot recover them.
- Route auto-generated Ollama configurations through LiteLLM's `ollama_chat/`
  provider so streamed tool calls retain their structure. Public model names
  remain `ollama/<model>`.
- Add `--no-thinking` to disable thinking in phase and utility queries. It
  overrides effort settings; existing behavior is unchanged without the flag.
- Add `--show-cli-stderr` to display agent CLI diagnostics in the dashboard and
  save them to `orchestrator.log`. Diagnostics remain suppressed by default.

The Ollama changes fix routing and add a compatibility option; they do not
establish that a particular local model can complete an investigation. See the
[usage guide](../usage-guide.md#local-models-with-ollama) for configuration.

## Forensic extraction and reporting

- Correct Chainsaw hunt mapping and SRUM invocation. SRUM requires the SOFTWARE
  hive alongside the SRUM database; nonzero Chainsaw exits are reported as errors.
- Index detection and artifact details from Chainsaw, Zircolite, MVT, ALEAPP, and
  iLEAPP so searches can find the records behind summary counts.
- Correct CAPA/FLOSS JSON flags and output parsing, including ATT&CK subtechniques
  and FLOSS runtime. Index derived binary triage findings and prevent incomplete
  rabin2 analysis from producing a benign verdict.
- Decode encoded PST headers, preserve quoted recipient names, search HTML-only
  message bodies and Cc/attachment names, and recognize named inline attachments.
- Return and index PDF URLs and embedded-file metadata when requested.
- Preserve deleted-file entries when parsing Sleuth Kit `fls` output across disk
  extraction tools.
- Decompress standalone gzip/bzip2 evidence files and distinguish completed
  archive extractions from partial attempts so failed runs can be retried.
- Escape finding titles in HTML reports while preserving executive-summary markup.

## Security and packaging

- Validate case IDs before opening databases and constrain explicit archive
  destinations to the extraction directory, including symlink resolution.
- Run radare2 command batches under its sandbox to block shell escapes, writes,
  and opening additional files.
- Reduce container runtime layers and development artifacts while retaining
  forensic tools and symbol packs. Add container runtime smoke checks to CI.

## Upgrade notes

- Install the updated Python package or pull `ghcr.io/calebevans/mulder:1.5.1`
  after the release is published. There are no case database schema changes.
- Existing case indexes are not rewritten by an upgrade. Rerun affected tools
  (using `force=True` where supported) when you need corrected extraction output.
- Custom Ollama proxy YAML should use `litellm_params.model: ollama_chat/<model>`
  while retaining an `ollama/<model>` public alias. Auto-generated configs handle
  this mapping automatically.
- Supply `software_hive_path` for Chainsaw SRUM mode. Hunt mode needs a mapping
  installed by `mulder setup` or supplied via `mapping_path`.
- CAPA results now use `capabilities[].attack[].subtechnique` for the name instead
  of the old always-null `subtechnique_id`. The full ID remains in `technique_id`.
- Run investigations as the `mulder` user when using `docker exec`:
  `docker exec -it -u mulder <container> bash`.

See the [tool manifest](../tool-manifest.md) for updated parameters and results.

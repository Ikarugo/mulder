## Analysis of Misses and Errors

### Same image, different path (items 2, 8, 9, 10, 14, 19 lost; 3, 4, 12, 18 gained)

The extractor output is the one run 1 consumed (masquerade 0 / 17 / 3 on rm1 / rm2 / rm3, `optical.listing` 58 lines, `ez.shimcache` 307, `bulk.url_searches` 155). Run 1 spent its `get_raw_output` calls on ShimCache, `bulk.url` and the registry `CurrentVersion` key and got CCleaner, Eraser, the Drive URLs, a search term and the OS edition; this run spent them on `USBSTOR`, ShellBags and `tsk.filelist` and got both serials, the share and the five filenames. Neither run did both. Six items go from PARTIAL to MISSED, four from MISSED to PARTIAL, and the count of detected items falls from 12 to 10.

### Registry queries that failed or were not written down (items 2, 20)

`TimeZoneInformation` was requested four times with key paths the tool rejected (a `SYSTEM\` prefix, then `Control\...`, `""`, `/`) and abandoned; `CurrentVersion\InstallDate` was requested once and its answer never reached a finding; `ProductName` was never requested. Run 1 reported the edition and install date from the same hive.

### Device facts retrieved and not joined (items 3, 4, 12)

The report has vendor, model, revision, both serials, three USBSTOR timestamps, rm2's FAT32 partition, size and label, and rm2's 16 disguised files, and never states which serial is which image. It also gives rm2 both volume labels and exFAT system files, and gives "REMOVABLE MEDIA 1 (FAT32 USB)" masqueraded files it does not have. The Kimi v1.5.2 report paired serial to image by list order and was FOUND on item 3; this one does not pair them at all.
